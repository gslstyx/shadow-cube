## 1. 立项概述

### 1.1 一句话描述
在一个三维立体空间中，玩家通过手指在水平平台上**生成 / 消除方块**来搭建立体造型，使该造型的**左侧投影**与**正投影**分别与左边、后边两面"墙"上的目标投影完全一致，即可过关。

### 1.2 参考图核心元素
- 极简黑白灰配色，等距（Isometric）视角
- 中央一块水平网格平台，用于摆放方块
- 左侧墙 + 后侧墙各显示一个目标投影剪影（黑色块状图形）
- 玩家搭建的立体图形实时投出影子，与目标比对

**参考图存档**：`docs/images/reference-01-light-theme.jpg`（2026-09-16 采集，用于后续复盘）

**参考图逐项拆解（2026-09-16 补录）**

| 维度 | 参考图实际表现 | 对实现的要求 |
|---|---|---|
| 整体色调 | **浅色系**：白/米白墙面 + 浅灰网格线 + 纯白背景；方块与墙上投影均为**近黑色** | ⚠️ 与 §2.3「深蓝紫底 + 青/品红点缀」冲突，需二选一（见 §8.4） |
| 视角 | 等距斜俯视，俯角约 **25°~30°**，正交感强 | 相机 pitch 范围需可调（§2.2-C 的 `pitchMin/pitchMax`） |
| 两面墙 | 位于平台**左后 / 右后**，成直角相交；墙面是**白色网格面板**（不是发光面） | 墙面 = 网格纹理背景板 + 投影块为实心暗块 |
| 目标投影 | 墙上**黑色实心矩形**，位于墙面中段（离地，不贴地） | 投影块按 `(u, y)` 定位，自下而上第 y 层；墙面高度须覆盖 `maxHeight` |
| 平台 | **白色线框薄板**（悬浮），上表面细分网格，四角有细线延伸至画面外 | 平台以"线框 + 极浅底色"为主，网格线是主要视觉 |
| 方块 | **黑色实心立方体**，棱边清晰，块与块之间**有缝** | 方块缩放 < 1（留缝），深色实体 + 描边 |
| 氛围 | 纯白、无雾、无粒子，克制到接近工程图 | 与 §2.3 的雾效/星尘/暗角**不一致**，需确认取舍（见 §8.4） |

### 1.3 核心体验目标
- **异次元空间感**：游玩界面要有"穿越到另一个维度"的沉浸感
- 极简、克制、干净的视觉语言（黑白灰 + 点缀色）
- 解谜的"顿悟"爽感：从两个二维投影反推出三维结构

## 2. 玩法需求

### 2.1 核心循环
1. 进入关卡 → 看到左右两墙上的目标投影 + 空平台
2. 手指在网格上**拖拽 → 连续生成方块**；对已有方块拖拽 → 消除；可**水平 + 垂直旋转**相机从多角度观察
3. 立体图形的投影实时渲染到两侧墙面上（投影重合时墙面对齐高亮）
4. 两面墙投影均与目标一致（集合匹配）→ 判定过关
5. 过关结算 → 解锁下一关

### 2.2 交互细节（已确认）

**A. 方块生成 / 消除**
- **拖拽连续生成**：手指按住并在网格上拖动，经过的位置连续生成方块（不抬起手指可连续"刷"出一排）。
- **消除**：对已有方块再拖拽经过 → 消除（或提供"建造 / 消除"模式切换按钮，待定，建议拖拽时自动判断：起始格为空 → 本次手势为生成；起始格为方块 → 本次手势为消除）。
- 方块生成 / 消除带短动画（缩放弹出 / 消散），反馈要跟手。

**B. 空间维度**
- 在**真 3D 体素空间**中搭建（非单层 2D 网格）。
- **多层叠放：全局开放**（已确认）。
- 高度上限 `maxHeight` 由关卡数据配置；前 10 关按 1→3 层渐进引入，后续系列可放开到更高（参数化，不改代码）。

**C. 相机旋转**
- 支持**水平旋转（绕 Y 轴）** + **垂直旋转（俯仰，绕 X 轴）**，两者都做，先出效果再看手感。
- **旋转后投影墙面跟随**：两面墙始终位于当前视角的"左 / 后"方向，随相机一起旋转，保证玩家永远能同时看到两个投影。
- **全部参数可调**（`CameraConfig`，Inspector / 配置文件可调，方便调手感）：
  | 参数 | 说明 | 初值建议 |
  |---|---|---|
  | `enableYaw` / `enablePitch` | 水平 / 垂直旋转开关 | true / true |
  | `snapEnabled` | 松手是否吸附 | true |
  | `snapAngle` | 水平吸附角度 | 90° |
  | `pitchMin` / `pitchMax` | 垂直俯仰范围 | 15° ~ 75°（避免到 90° 顶视导致投影读不出） |
  | `rotateSensitivity` | 拖动灵敏度 | 0.3 |
  | `damping` | 回弹/跟随阻尼 | 0.15 |
- 吸附：连续拖动 + 松手吸附到最近的 `snapAngle`，避免斜视导致投影读不准（可关闭做自由视角对比测试）。
- **投影互换规则：采用方案 A** —— 判定按"**两墙投影集合匹配**"处理（两面墙的投影与两个目标投影一一对应即可），不强制哪面墙对应哪个投影，旋转后玩家无感。（方案 B 作为后备，看效果再决定）

**D. 重置**
- HUD 提供 **🔄 重置按钮**，清空本关所有方块，重新开始（带二次确认动效或直接执行，建议直接执行 + 短动效）。

**E. 新手引导**
- **第 1 关做引导**：分步高亮教学（拖拽生成 → 拖拽消除 → 旋转相机 → 观察投影 → 过关）。
- 引导用遮罩 + 手指动画 + 文案，可跳过；仅首次游玩触发，存档记录。

**F. 提示系统**
- 定位：**只做"开头操作提示"**，不直接给完整解。
- 点击 💡 提示 → 播放一段**实时动画演示**，内容限定为：
  1. **如何旋转镜头**（相机自动旋转到推荐视角，手指动画示意拖动方向）
  2. **如何拖拽生成 / 消除方块**（在平台上演示一次拖拽手势 → 生成方块 → 再拖一次 → 消除）
- 演示结束后停在**引导姿态**，由玩家自己继续解谜（保留解谜乐趣）。
- 后续（M5 之后）可再考虑扩展到"下一步最优解"提示，作为更高阶的付费/广告点。

**G. 提示的免费与广告规则（已确认）**
- **第 1~5 关：提示免费**（不限次数，配合新手引导期）。
- **第 6 关起：看一次激励视频广告 → 获得一次提示**。
- 广告 SDK 接入：**TODO（M5 阶段）**，前期先打 `IAdService` 空实现接口，逻辑层按"免费/需广告"开关走，接 SDK 时只替换实现（见 §6.1）。

### 2.3 判定规则（已确认）

**A. 比对方式：逻辑比对（非像素级）**
- 把玩家方块集合分别沿两个投影方向做**布尔投影**（体素 → 平面格占用表），与目标投影做**按格逻辑比对**。
- **判定条件：投影重合即可过关** —— 即允许存在"额外的、被完全遮挡的方块"，只要两面墙的投影与目标一致即判胜。
- 优点：容错好、解法多样、不会出现边缘像素抖动导致的误判；性能 O(n)，极低端机也无压力。

**B. 星级评价（最高 5 星）**
- **按所用方块数量**评级，以关卡设定的"最少方块数 `optimalCount`"为基准：

| 星级 | 条件（建议） |
|---|---|
| ⭐⭐⭐⭐⭐ | 方块数 == `optimalCount`（最优解） |
| ⭐⭐⭐⭐ | ≤ `optimalCount` + 1~2 |
| ⭐⭐⭐ | ≤ `optimalCount` + 3~4 |
| ⭐⭐ | ≤ `optimalCount` + 5~6 |
| ⭐ | 通关即可 |

- `optimalCount` 由关卡数据给出（可用求解器自动计算校验）。
- 星级存档取历史最好成绩，可在选关界面展示。

## 3. 界面需求

### 3.0 美术风格（已确认）
- **科幻线框风（Sci-Fi Wireframe）**：以线框 / 边缘光 / 半透明发光网格为主，深空背景 + 霓虹点缀色。
- 统一要素：
  - 方块：半透明体积 + 高亮描边（线框感）
  - 平台：发光网格地面，带扫描线/网格呼吸动效
  - 投影墙：**墙面灰白 + 目标投影灰黑**，玩家投影与目标**重合则变绿**、**超出（未被目标覆盖）则为蓝** —— ✅ **已确认，所有关卡通用（不随系列/主题变化）**，直观反馈"对上了 / 多出来了"
  - 背景：深空/星尘粒子 + 缓慢漂浮的线框几何体，强化异次元感
- 配色：深蓝紫底 + 青色/品红点缀（后续可换主题色，见 §4.3 系列化）。

### 3.1 首页（Main Menu）
- **空间立体感、酷炫**：背景使用 3D 场景（漂浮旋转的线框几何体 / 星尘粒子 / 视差层），营造异次元氛围
- 主要按钮：
  - **进入游戏**（直接进入最新解锁的关卡）
  - **选择关卡**（进入关卡选择界面）
  - **⚙ 设置**（首页右上角小图标，不抢主按钮视觉）
- 设置面板（弹层/二级页）内容：
  - **🌐 语言切换：简体中文 / English**（已确认入口在首页设置里）
  - 🔊 音乐音量 / 音效音量（滑条）
  - （后续预留）振动开关、Google Play Games 登录状态、隐私政策 / 关于
- 设置中的语言切换**即时生效**，无需重启（刷新 String Table 事件）

### 3.2 关卡选择界面
- **可扩展架构**：关卡数据以"章节 / 系列（Series）+ 关卡包（Level Pack）"形式组织
- 已解锁关卡可点击，未解锁关卡显示锁图标
- **解锁规则：严格线性，通关第 N 关才能解锁第 N+1 关**
- 每个关卡格显示：关卡号 + 历史星级
- 提供**返回首页**按钮（左上角 ←）
- 支持后续以**更新扩展包（DLC / 热更资源包）**形式追加系列，无需发版

### 3.3 游玩界面
- 布局：左侧投影墙、后侧投影墙、中央平台（参考图）
- 异次元氛围：雾效、暗角、星尘粒子、悬浮网格、低频环境音
- HUD：
  - 左上：返回（回选关界面）
  - 右上：🔄 重置
  - 右下：💡 提示
  - 顶部中央：关卡号 / 系列名 + 当前方块数

### 3.4 结算界面（已确认）
- 过关动效（投影墙放光 / 方块爆散 / 线条汇聚）
- 展示获得的星级（动画点亮）
- 三个按钮：**重玩**、**下一关**、**返回关卡**（回到选关界面；选关界面可再返回首页）

## 3.5 音频需求（新增）

风格总纲：**轻柔、空灵、干净的科幻空间感**，音量克制，不喧宾夺主。

| 类型 | 场景 | 音色要求 |
|---|---|---|
| **BGM 背景音** | 首页 + 游玩 + 选关 | 轻柔、空灵（Ambient / Pad 铺底 + 稀疏音符），循环无缝、无强节奏，长时间游玩不疲劳。**当前：首页与关卡内共用同一首 BGM；后续支持按系列主题单独配置** |
| **按钮反馈音** | 所有 UI 按钮点击 | 轻快的键盘/机械短音（"嗒"），短促清脆，< 150ms |
| **方块新增** | 拖拽生成方块 | **垒砖音**：低沉短促的"咚/咔哒"，带一点材质撞击感；连续拖拽时要做**节流 + 音高微随机**，避免连点爆音 |
| **方块消除** | 拖拽消除方块 | **方块敲碎音**：干脆的碎裂声（"咔嚓"），比生成音更亮更短；同样做节流 + 随机音高 |
| **镜头调整** | 旋转相机（水平/垂直） | **转动轮盘音**：低音量、细腻的机械阻尼摩擦声（"咝—"），随旋转速度变化音量/音高，松手停止 |
| （补充）过关音 | 结算界面 | 上行琶音 + 空灵尾音（与星级数联动更好） |

**技术要求**
- 使用 Unity **AudioMixer** 分总线：`Master / BGM / SFX`，设置里的音量滑条分别控制 BGM 与 SFX。
- 音效走 `AudioService` 统一播放接口（播放、随机音高、节流、3D/2D 切换），禁止各处直接 `PlayOneShot` 硬写。
- 资源格式：短音效 **WAV/PCM（解压后播放，极低延迟）** 或 ADPCM；BGM **Vorbis/OGG（流式）**，Load Type = Streaming。
- 连续触发音效（生成/消除/旋转）必须做**最小间隔节流**（建议 40~60ms）+ **音高 ±5% 随机**，否则会出现刺耳叠加。
- 音频不随场景销毁：用 `DontDestroyOnLoad` 的 `AudioService` + 场景切换时 BGM 交叉淡入淡出。
- **BGM 配置（已确认）**：当前全场景共用 1 首 BGM（`AudioService` 播放 `bgm_default`）；架构上按 **`bgmKey`** 取音源，系列数据（§4.2）可配置 `bgmKey`，未来新增系列主题只需加音频资源 + 填 key，不改代码。
- 静音/后台：`ApplicationFocus` 与系统静音时暂停 BGM。

## 4. 关卡数据与扩展方案

### 4.1 数据格式
- 关卡定义为**数据驱动**（ScriptableObject 或 JSON）：
  - 平台尺寸（NxM）+ 高度上限 `maxHeight`
  - 标准解方块布局（即最优答案）
  - `optimalCount`：最少方块数（可由标准解自动算出，用于星级评定）
  - 目标投影：由标准解**自动计算生成**（避免手画两份出错）
  - 系列 ID / 关卡包 ID / 关卡序号、难度标签、主题风格配置

### 4.2 系列化设计（已确认方向）
- **每一系列（Series）拥有独立的美术风格或玩法变体**，后续作为扩展包发布：
  - 风格维度：配色主题（青/紫/橙…）、材质（线框/实体/玻璃）、背景场景（深空/网格都市/液态空间）
  - 玩法维度（待扩充候选）：
    - 基础投影（两个投影）
    - 三面投影（增加俯视/顶面投影）
    - 限色方块（不同颜色的方块需匹配对应投影颜色）
    - 障碍物 / 固定不可动方块
    - 限步数 / 限时
    - 镜像 / 对称约束
- 系列数据里配置"风格主题 + 玩法规则开关"，新系列 = 新数据 + 新资源组，不改动核心代码。

### 4.3 前期关卡规划（已确认）
- **先做 1 个系列、10 个关卡**做实验验证玩法与数据管线。
- 建议难度曲线（可调整）：

| 关卡 | 目标 |
|---|---|
| 1 | 引导关：单层、3 块以内，教拖拽生成 / 消除 |
| 2 | 教授旋转：需转动视角才能判断的解 |
| 3~4 | 双层引入 |
| 5~7 | 3 层 + 遮挡关系（引入"投影重合"的巧解） |
| 8~10 | 综合，方块数 10~15，需要多次旋转观察 |

### 4.4 扩展包机制
- 使用 **Addressables** 管理关卡资源，支持远程 CDN 热更
- 新章节 = 新增一个关卡包数据 + 资源组，通过更新扩展包下发
- 关卡校验：下载后做版本号 + 完整性校验

## 5. 非功能需求

## 6. 商业化与合规（海外）

### 6.1 商业化（已确认方向）
- 模式：**免费下载 + 激励视频广告**（后续可加去广告内购）。
- 广告变现点：**提示功能** —— 玩家点击 💡 提示 → 观看激励视频 → 获得一次提示演示。
- **免费规则（已确认）：第 1~5 关提示免费；第 6 关起需观看激励视频。**
- （无内购版本：不接 Google Play Billing，收益仅来自激励视频；如后续加"去广告"再补内购。）

### 6.1.1 Google Play Games 服务（已确认接入，M5）
- **云存档（Saved Games）**：本地存档为主，登录 GPGS 后自动同步；冲突策略 = **进度更高者胜**（已解锁关卡数 + 总星数）。
- **成就（Achievements）**：建议首批成就 —— 首次通关、首次 5 星、累计通关 10 关、通关某系列全部关卡、无提示通关一关。
- **排行榜（Leaderboards）**：可选（总星数排行），待定。
- 接入方式：Google Play Games plugin for Unity（见环境文档），**前期同样走 `ICloudSaveService` 空实现**，M5 替换。
- 注意：需在 Google Play Console 创建游戏、配置 OAuth、上传 SHA-1 指纹（上传密钥 + 应用签名密钥都要）。
- **SDK 接入：TODO（M5）**。前期定义 `IAdService` 接口 + `NullAdService` 空实现，逻辑层只依赖接口；M5 时替换为 **Google AdMob**（海外填充率与合规最好，备选 Unity Ads / LevelPlay）。
- 广告接入要点：
  - 必须在**隐私政策 + Google Play 数据安全表单**中声明广告 ID 收集
  - Android 13+ 需处理广告 ID 权限；遵守 GDPR / CCPA（欧洲/加州需 consent 弹窗，建议用 UMP SDK）
  - 家庭向/儿童向需避免个性化广告（按目标受众设定，见 §6.2）

### 6.2 发布与合规
- 目标商店：Google Play（后续可扩 iOS App Store、Steam 等）
- 海外版**不含**：国内实名认证、防沉迷、版号相关逻辑
- 需处理：Google Play 数据安全表单、隐私政策页、目标受众与内容分级问卷、广告 ID 声明
