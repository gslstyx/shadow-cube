# 测试文档（Shadow Cube）v1.0

> 范围：M1 玩法原型 → M5 上架全过程的测试方案与测试用例
> 平台：Android（真机 ARM64 + 模拟器 x86_64），Android 8.0 (API 26) 及以上
> 关联文档：`01_需求文档.md`、`03_打包发布流程文档.md`

---

## 1. 测试目标与质量目标

| 质量属性 | 目标值 |
|---|---|
| 崩溃率（Crash-free sessions） | ≥ 99.5% |
| ANR 率 | ≤ 0.2% |
| 帧率 | 中低端机 ≥ 30 fps；主流机 ≥ 55 fps |
| 冷启动时间（中端机） | ≤ 3 s |
| 首包体积 | < 80 MB |
| 内存峰值（低端机） | ≤ 350 MB |
| 核心玩法用例通过率（准出） | 100%（P0） |
| 全部用例通过率（准出） | ≥ 98%，且无未关闭 P0/P1 缺陷 |

## 2. 测试分层

| 层级 | 内容 | 工具 | 执行频率 |
|---|---|---|---|
| **L0 单元测试** | 投影布尔计算、判定逻辑、星级计算、关卡数据校验、存档序列化 | Unity Test Framework（EditMode） | 每次提交 / CI |
| **L1 集成测试** | 输入 → 体素变更 → 投影更新 → 判定 → 存档链路 | Unity Test Framework（PlayMode） | 每日 |
| **L2 系统功能测试** | 手工用例（本文 §5） | 真机 + 模拟器 | 每里程碑 / 回归 |
| **L3 性能测试** | 帧率、内存、启动、耗电、发热 | Unity Profiler、Android Studio Profiler | 每周 / 每里程碑 |
| **L4 兼容测试** | 系统版本、架构、分辨率、厂商 ROM | 设备矩阵 + 模拟器 | 每里程碑 |
| **L5 合规与发布测试** | 隐私政策、数据安全、target API、包内容、商店素材 | Play Console 预发布报告 | 上架前 |

## 3. 测试环境

### 3.1 设备矩阵

| 类型 | 配置 | 用途 |
|---|---|---|
| **低端真机** | Android 8.0 / ARM64 / 2–3 GB RAM / 720p | 性能下限、内存、兼容性 |
| **主流真机** | Android 12–14 / ARM64 / 6–8 GB RAM | 主测机、手感、视觉 |
| **高端真机** | 最新旗舰 | 上限、发热 |
| **模拟器（x86_64）** | Android Studio 模拟器，API 26 / 30 / 34 | 架构兼容、快速回归、CI |
| **平板（可选）** | Android 平板 / 大屏 | 布局适配 |

> 模拟器必须使用 **x86_64** 镜像，验证 `debug` 包的多架构支持；真机验证 **ARM64**。

### 3.2 工具

- Unity Profiler / Memory Profiler（开发版包）
- Android Studio Logcat、`adb`（安装、日志、截图、录屏）
- `adb install -r <apk>`、`adb shell am start -n <pkg>/com.unity3d.player.UnityPlayerActivity`
- Google Play Console 预发布报告（上架前自动跑兼容性）

## 4. 测试流程

| 阶段 | 内容 | 产出 |
|---|---|---|
| **每日构建冒烟**（15 min） | 装最新 debug 包 → 跑 SMOKE-01~08 | 冒烟结论（通过 / 阻塞） |
| **里程碑回归**（每里程碑 1–2 天） | 全量功能用例 + 性能基线采集 | 回归报告 |
| **发布前全量**（上架前 3 天） | 功能 + 性能 + 兼容 + 合规全量 | 发布准出报告 |
| **灰度观察**（发布后 24–72 h） | 崩溃 / ANR / 评分 / 关键漏斗 | 灰度结论 |

**准入标准（开始测试）**：包能安装启动、无 P0 阻塞、版本号正确、主要功能入口可达。
**准出标准（允许发布）**：P0 缺陷 0、P1 ≤ 2 且已有规避方案、核心用例 100% 通过、性能指标达标、合规项全绿。

|---|---|---|
| **P0 阻断** | 崩溃、无法启动、核心玩法不可用、数据丢失、无法发版 | 立即修，当日 |
