# 开发协作约定（Shadow Cube）v1.0

> 目标：**改得动、跑得起来、留得下痕迹**
> 适用：本仓库所有代码、配置、文档变更

---

## 1. 核心约定（必须遵守）

> **完成「较大调整」后，自动进行体检，体检通过则提交并推送到远端。**

### 1.1 什么算「较大调整」

满足**任意一条**即触发体检 + 提交推送流程：

| 类型 | 示例 |
|---|---|
| 新增/重构模块 | 打包管线、混淆模块、玩法核心系统 |
| 引擎/环境变更 | Unity 版本、渲染管线、构建配置、包名 |
| 新增文档或大段修订 | 新增 `docs/0x_*.md`、重写章节 |
| 公共配置变更 | `BuildConfig/build.json`、`.gitignore`、`.gitattributes` |
| 影响构建的设置 | Player Settings、包依赖、脚本后端 |
| 里程碑完成 | M0 / M1 / … 任一阶段收尾 |

**不触发**（可先攒着）：单行文案修正、注释调整、临时调试文件（且未入库）。

### 1.2 体检内容

执行 `./tools/healthcheck.sh`（可选 `--build` 追加一次联调包构建）：

1. **工具链**：git / git-lfs / Unity 是否就绪，`BuildConfig/build.json` 是否存在
2. **编译**：Unity 无头编译 C#，出现 `error CS` 即失败
3. **Git 卫生**：
   - 密钥类文件（keystore / jks / key）不得入库
   - 大于 5 MB 的文件必须走 LFS（依据 `.gitattributes`）
   - 提示未跟踪文件，确认是否遗漏入库
4. **文档同步**：`docs/01~05` 齐全
5. **（可选）构建验证**：跑一次 `./tools/build.sh debug`

退出码：`0` 通过（可提交推送）／`1` 失败（先修复）。

### 1.3 流程

```
较大调整完成
   ↓
体检 ./tools/healthcheck.sh
   ↓ 通过
提交（Conventional Commits）
   ↓
推送 git push origin main
   ↓
向用户汇报：提交号 + 变更清单 + 体检结论 + 遗留项
```

**体检未通过时禁止推送**，先修复并重新体检。

## 2. 提交规范

采用 [Conventional Commits](https://www.conventionalcommits.org/)：

```
<type>(<scope>): <简述>

<body：为什么改、改了什么、影响面>
```

| type | 用途 |
|---|---|
| `feat` | 新功能 / 新模块 |
| `fix` | 缺陷修复 |
| `docs` | 仅文档 |
| `refactor` | 重构（无功能变化） |
| `perf` | 性能优化 |
| `build` | 构建/打包/依赖 |
| `chore` | 杂项（忽略规则、脚手架） |

示例：

```
feat(build): 打包管线加入可开关的代码混淆

- 新增 ShadowCubeObfuscation：IL2CPP 前处理托管 DLL
- level 0/1/2/3 可配置，联调包强制关闭
- 文档：03 新增 §5、04 新增 TC-BUILD-13~18
```

**提交粒度**：一个逻辑变更一次提交，禁止把无关改动混在一起。

## 3. 分支与推送

| 项 | 约定 |
|---|---|
| 主分支 | `main`（唯一长期分支） |
| 日常开发 | 直接在 `main`；里程碑大改可开 `feature/*`，合并后删除 |
| 推送时机 | 体检通过后立即推送，避免本地堆积 |
| 禁止 | `push --force`、`--no-verify`、绕过钩子 |

---

## 4. 安全红线

- ❌ 绝不提交：`*.keystore`、`*.jks`、`*.key`、`BuildConfig/keystore.json`（已在 `.gitignore`）
- ❌ 绝不提交：构建产物 `Builds/`、Unity 缓存 `Library/`、`.utmp/`
- ❌ 绝不在日志/文档/提交信息中出现密钥、口令、令牌
- ✅ 大文件（贴图/音频/模型/字体）必须经 Git LFS（规则见 `.gitattributes`）

---

## 5. 文档同步约定

改动涉及下列内容时，**同一次调整必须同步更新对应文档**：

| 变更 | 需更新文档 |
|---|---|
| 环境 / 版本 / 包名 | `02_开发环境文档.md` |
| 打包 / 签名 / 发布 | `03_打包发布流程文档.md` |
| 影响玩法或验收标准 | `01_需求文档.md` + `04_测试文档.md` |
| 新增流程/约定 | `05_开发协作约定.md` |

---

## 6. 常用命令速查

```bash
./tools/healthcheck.sh            # 快速体检
./tools/healthcheck.sh --build    # 完整体检（含联调包构建）
./tools/build.sh debug            # 打联调测试包（APK，真机+模拟器）
./tools/build.sh release          # 打正式包（AAB，签名）
git add -A && git commit -m "..."  # 提交
git push origin main              # 推送
```
