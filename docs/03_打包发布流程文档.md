# 打包发布流程文档（Shadow Cube / Android）v1.0

> 目标：**傻瓜式打包** —— 一条命令 / 一个菜单项出包，不需要懂 Unity 也能打
> 覆盖：**联调测试包**（真机 + 模拟器）与 **正式包**（Google Play 上架）
> 架构支持：**ARM64（真机）+ x86_64（模拟器）**
> 当前基线：Unity **6000.3.24f1** / 工程 `ShadowCube/`

---

## 1. 包类型矩阵

| 维度 | 联调测试包（debug） | 正式包（release） |
|---|---|---|
| 产物格式 | **APK**（可直接 `adb install`） | **AAB**（上架 Google Play） |
| 目标架构 | ARM64 + x86_64 | ARM64 + x86_64 |
| 脚本后端 | IL2CPP | IL2CPP |
| Development Build | ✅ 开 | ❌ 关 |
| 脚本调试 / Profiler | ✅ 开（可 attach、可连 Profiler） | ❌ 关 |
| 编译符号 | `SC_DEV` | 无 |
| 签名 | debug keystore（自动） | **上传密钥**（`BuildConfig/keystore.json`） |
| 代码加固 / 混淆 | ❌ 强制关闭（保证可调试） | ✅ 按 `obfuscation` 配置（见 §5） |
| 版本号 | `versionCode` 自动 +1 | `versionCode` 自动 +1 |
| 产物命名 | `ShadowCube-dev-v{ver}+{code}_{时间戳}.apk` | `ShadowCube-release-v{ver}+{code}_{时间戳}.aab` |
| 主要用途 | 真机联调、模拟器验证、性能抓帧、QA 测试 | 内部/封闭/公开测试轨道、正式上架 |
| 预计耗时 | 实测 **23 分 18 秒**（双架构 IL2CPP，Intel i7 / 16 GB） | 同左 |
| 实测产物 | `ShadowCube-dev-v0.1.0+2_20260915_0340.apk`（**73 MB**，含 `arm64-v8a` + `x86_64`） | 待首次 release 构建 |
| **能否上架** | ❌ 否 | ✅ 是 |

> **已实测**（2026-09-15）：`./tools/build.sh debug` → `Succeeded`，0 错误，产物 73 MB，`unzip -l` 确认同时含 `lib/arm64-v8a/` 与 `lib/x86_64/`，可分别用于真机与 x86_64 模拟器。
>
> 32 位（ARMv7）默认未包含；如需覆盖老旧 32 位设备，在 `ShadowCubeBuildPipeline.ApplyDevelopmentSettings()` 中加回 `AndroidArchitecture.ARMv7`（会使构建时间变长）。

## 2. 傻瓜式打包：两种方式（二选一）

### 方式 A：终端一条命令（推荐，无需打开 Unity）

```bash
cd ShadowCubeProject
./tools/build.sh debug      # 联调测试包
./tools/build.sh release    # 正式包
BOUNCE=1 ./tools/build.sh debug   # 构建完自动打开产物目录
```

| 参数 / 环境变量 | 说明 |
|---|---|
| `debug` / `release` | 包类型（也接受 `dev`/`test`、`prod`） |
| `UNITY_PATH=/path/to/Unity` | 指定 Unity 可执行文件（换版本时用） |
| `BOUNCE=1` | 构建成功后在 Finder 打开产物目录 |

脚本行为：切 Android 平台 → 应用配置 → `versionCode` +1 → 构建 → 打印产物路径 → 写入 `Builds/Android/last-build.txt`。

### 方式 B：Unity 编辑器菜单（所见即所得）

```
Unity 顶部菜单 → Tools → Shadow Cube
  ├─ 1) 一键打包 · 联调测试包 (APK / 全架构 / 可调试)
  └─ 2) 一键打包 · 正式包 (AAB / 64位 / 签名)
```

点完等进度条结束，产物路径见 Console 中 `[ShadowCube] 产物: ...`。

### 产物位置

```
ShadowCube/Builds/Android/
  ├── ShadowCube-dev-v0.1.0+2_20260915_0340.apk
  ├── ShadowCube-release-v0.1.0+3_20260915_0410.aab
  └── last-build.txt          ← 最近一次产物绝对路径（CI/脚本读取）
```

## 3. 首次使用：三步准备

### 3.1 配置包名（**上架后不可修改，务必先定稿**）

编辑 `ShadowCube/BuildConfig/build.json`（**入库**）：

```json
{
  "packageName": "com.gslstyx.shadowcube",
  "companyName": "gslstyx",
  "productName": "Shadow Cube",
  "minSdkVersion": 26
}
```

> `packageName` 规则：全小写、至少两段、不得含 `unity`/`android` 保留词；Google Play 上架后**永久不可改**。

### 3.2 生成上传密钥 + 启用 Play App Signing（仅正式包需要）

```bash
keytool -genkeypair -v \
  -keystore ~/keystores/shadowcube-upload.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias shadowcube-upload
```

1. 在 Google Play Console 创建应用 → **启用 Play App Signing**（由 Google 保管应用签名密钥）。
2. 把生成的 **上传密钥** 注册到 Play Console。
3. 本地填写 `ShadowCube/BuildConfig/keystore.json`（**不入库，已在 `.gitignore` 中排除**）：

```json
{
  "keystoreName": "/Users/you/keystores/shadowcube-upload.jks",
  "keystorePass": "********",
  "keyaliasName": "shadowcube-upload",
  "keyaliasPass": "********"
}
```

> ⚠️ 上传密钥丢失 = 无法再更新应用。必须异地备份，且**禁止提交到 Git**（`.gitignore` 已排除 `BuildConfig/keystore.json`）。
> 未配置时脚本会回退到 debug keystore 并**打印警告**，该包**不可上架**。

### 3.3 版本号规范

| 项 | 位置 | 规则 |
|---|---|---|
| `versionName` | `Player Settings → Version` | 语义化 `主.次.修订`（如 `0.1.0`）；对外展示 |
| `versionCode` | 脚本**自动 +1** | 单调递增整数，Google Play 要求每次上传必须比上次大 |

发版前手动改 `bundleVersion`（如 `0.1.0` → `0.2.0`），`versionCode` 无需手工干预。

## 4. 构建前检查清单（Pre-build Checklist）

- [ ] 场景已加入 **Build Settings → Scenes In Build**（或存在 `Assets/Scenes/Bootstrap.unity` 兜底）
- [ ] `BuildConfig/build.json` 包名已定稿
- [ ] 正式包：`keystore.json` 已配置且可读取
- [ ] Console 无编译错误（`error CS`）
- [ ] 磁盘可用 **≥ 15 GB**（IL2CPP 中间产物 + Gradle 缓存）
- [ ] 开启混淆/剥离时：反射相关类型已加入 `Assets/Link.xml`（见 §5.3）
- [ ] 目标设备/模拟器已就绪（x86_64 模拟器需先启动）
- [ ] Git 工作区已提交，构建分支明确

## 5. 代码混淆与加固（可开关）

开关位置：`ShadowCube/BuildConfig/build.json → obfuscation`

```json
"obfuscation": {
  "enabled": true,            // 总开关：false = 完全不加固
  "level": 1,                 // 0=关闭 1=内置加固 2=托管DLL名称混淆 3=第三方商业混淆器
  "managedStrippingLevel": "Medium",  // Minimal/Low/Medium/High/Disabled
  "minifyJava": true,         // Java 层 R8 压缩与混淆
  "externalCommand": "",      // 外部混淆器命令，{DIR} = 程序集目录
  "targetAssemblies": "Assembly-CSharp.dll,Assembly-CSharp-firstpass.dll"
}
```

### 5.1 三个级别

| 级别 | 做了什么 | 适用 | 风险 |
|---|---|---|---|
| **0 关闭** | 不做剥离、不混淆 | 联调包（默认强制） | — |
| **1 内置加固**（默认） | IL2CPP 原生化 + `stripEngineCode` + 托管代码剥离（Medium）+ Java R8 | 正式包 | 低；反射调用需进 `Link.xml` |
| **2 名称混淆** | 在 level 1 基础上，IL2CPP **之前**调用外部工具重命名托管 DLL 的类型/方法/字段 | 需要提高反编译门槛时 | 中；需白名单，务必回归 |
| **3 商业混淆器** | 同上，改为调用商业工具 CLI（如 Beebyte / Guardsquare） | 有预算、要字符串加密等 | 按厂商说明 |

### 5.2 怎么开 / 怎么关

| 方式 | 操作 |
|---|---|
| 改配置 | 编辑 `build.json` 的 `obfuscation.enabled` / `level` |
| Unity 菜单 | `Tools → Shadow Cube → 3) 切换代码混淆开关`（一键翻转 `enabled`，并打印当前 level） |
| 命令行 | `-executeMethod ShadowCube.EditorTools.ShadowCubeObfuscation.Toggle` |

> **联调包（debug）永远不做剥离与混淆**，保证可断点、可 Profiler，与配置项无关。
> **正式包**按 `build.json` 执行；`enabled=false` 时自动回退为不剥离、不 R8。

### 5.3 剥离白名单（重要）

`ShadowCube/Assets/Link.xml` 已预置 Addressables、ResourceManager、Localization 的 `preserve="all"`。
**凡是走反射/序列化/Addressables 按地址加载的类型都必须加进 Link.xml**，否则 `Medium/High` 剥离后运行时报「类型找不到」。

```xml
<assembly fullname="Assembly-CSharp">
  <type fullname="ShadowCube.Data.LevelData" preserve="all" />
</assembly>
```

### 5.4 接入外部混淆器（level 2/3，可选）

1. 安装工具（以开源 **Obfuscar** 为例）：`dotnet tool install -g Obfuscar`
2. 准备 `obfuscar.xml`（Input 指向 `{DIR}`，Output 覆盖回 `{DIR}`，并排除 Unity/第三方程序集）
3. 填写：

```json
"level": 2,
"externalCommand": "obfuscar.console /Users/you/obfuscar.xml && cp /tmp/obfout/*.dll {DIR}/"
```

执行时机：`IPostBuildPlayerScriptDLLs`（脚本 DLL 编译后、IL2CPP 之前），日志前缀 `[ShadowCube][混淆器]`；命令返回非 0 会**让构建失败**（避免悄悄产出未混淆包）。
未配置 `externalCommand` 时只打印警告并跳过，不会中断构建。

## 6. 发布流程（Google Play）

```
1) 打正式包        ./tools/build.sh release
2) 自检           见《测试文档》§发布前冒烟用例（BUILD-xx / COMPLI-xx）
3) 上传 AAB        Play Console → 对应轨道 → Upload
4) 填写商店信息    标题 / 简短描述 / 完整描述 / 截图（手机 2–8 张）/ 图标 512×512 / 特性图 1024×500
5) 合规材料        隐私政策 URL、数据安全表单、目标受众与内容分级问卷、广告声明（含激励视频时勾选）
6) 分级与受众      勾选"不含敏感内容"；若面向儿童需单独声明（本项目目标为一般受众）
7) 测试轨道        内部测试（最快 15 分钟生效）→ 封闭测试 → 公开测试 → 正式发布
8) 灰度发布        建议先 20% 灰度，观察 24h 崩溃/ANR 无异常后全量
9) 归档            AAB 与 `versionCode` 记录到发布台账，产物保留 ≥ 6 个月
```

**Time-to-Review**：首次提交审核通常 1–7 天，建议首个版本提前 1 周提交。

## 7. 常见问题与排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `Aborting batchmode: Scripts have compiler errors` | C# 编译错误 | 看 `Builds/unity-build-*.log` 搜 `error CS` |
| Gradle 卡住 / `Could not resolve` | 依赖下载失败或网络受限 | 使用可访问国际网络的环境；必要时配置 Gradle 代理 |
| 构建时磁盘写满 | IL2CPP + Gradle 中间产物大 | 保证 ≥15 GB；清理 `ShadowCube/Library/Bee`、`~/.gradle/caches` |
| `Keystore was tampered with / password incorrect` | keystore 配置错误 | 核对 `keystore.json` 四项；密码含特殊字符需转义 |
| 安装包在模拟器上提示 `INSTALL_FAILED_NO_MATCHING_ABIS` | 未打 x86_64 架构 | 用 `debug` 配置（含 x86_64）；正式包如需模拟器验证，确认 `targetArchitectures` 含 `X86_64` |
| 真机提示解析包失败 | APK 未签名或架构不含 ARM64 | 用 `debug` 包；正式包走 Play 分发 |
| 上传被拒：`target API 过低` | Target API 落后 | 保持 `Target API = Automatic (Highest Installed)`（脚本已设） |
| 构建极慢 | 首次 IL2CPP 全量编译 | 属正常；后续增量构建会明显加快，勿中断 |

## 8. 目录与文件约定

| 路径 | 作用 | 是否入库 |
|---|---|---|
| `tools/build.sh` | 一键打包脚本 | ✅ |
| `tools/healthcheck.sh` | 一键体检（编译 + Git 卫生 + LFS + 文档，可加 `--build`） | ✅ |
| `ShadowCube/Assets/Editor/ShadowCubeBuildPipeline.cs` | 打包管线（菜单 + CLI 入口） | ✅ |
| `ShadowCube/BuildConfig/build.json` | 包名 / 产品名 / 最低 SDK | ✅ |
| `ShadowCube/BuildConfig/keystore.json` | 签名密钥（**机密**） | ❌（已 gitignore） |
| `ShadowCube/Builds/` | 构建产物与日志 | ❌（已 gitignore） |
| `ShadowCube/Builds/Android/last-build.txt` | 最近产物路径 | ❌ |

**CLI 入口（CI 用）**：

```bash
/Applications/Unity/Hub/Editor/6000.3.24f1/Unity.app/Contents/MacOS/Unity \
  -batchmode -quit \
  -projectPath "$PWD/ShadowCube" \
  -executeMethod ShadowCube.EditorTools.ShadowCubeBuildPipeline.BuildDevelopment  # 或 BuildRelease
  -logFile "$PWD/Builds/unity-build.log"
```
