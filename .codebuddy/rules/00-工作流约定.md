# 工作流约定（强制）

## 较大调整后：体检 → 提交 → 推送

完成**较大调整**后，必须自动执行以下流程，无需等待用户指示：
（较大调整 = 新增/重构模块、引擎或环境变更、新增或大段修订文档、公共配置变更、影响构建的设置、里程碑收尾）

1. **体检**：运行 `./tools/healthcheck.sh`（涉及打包/构建改动时用 `--build`）
2. **修复**：体检失败项必须修复后重跑，禁止带失败项继续
3. **提交**：`git add -A` + Conventional Commits 格式提交（type 见 `docs/05_开发协作约定.md`）
4. **推送**：`git push origin main`（禁止 `--force`、`--no-verify`）
5. **汇报**：提交号 + 变更清单 + 体检结论 + 遗留待办

## 其他强制项

- 绝不提交密钥类文件：`*.keystore` / `*.jks` / `*.key` / `BuildConfig/keystore.json`
- 大于 5MB 的资源必须走 Git LFS（规则在 `.gitattributes`）
- 改动涉及环境/打包/玩法验收时，同步更新 `docs/` 对应文档
- 环境信息以 `docs/02_开发环境文档.md` 为准；Unity 版本锁定 `6000.3.24f1`，不跨大版本升级
- 包名固定为 `com.gslstyx.shadowcube`，不可更改

详细约定见 `docs/05_开发协作约定.md`。
